# PR の作成と更新

依頼範囲、既存変更、現在の branch、`develop` との差分、同じ head の既存 PR を確認する。
既存 PR があればその URL を使って更新する。対象だけを commit・push し、base は `develop` にする。
比較先が存在しない場合はリモートとユーザーの意図を確認し、別 branch を無断で代用しない。

## 検証

[AGENTS.md](../../../AGENTS.md) と [README](../../../README.md#検証) に従い、
実行したコマンド・結果・対象 commit・未検証事項を残す。
依存更新なら pub コマンドで lockfile を更新し、生成と全体検証を確認する。
UI 変更なら対象 platform の実行結果、画面条件、確認できた操作を記す。
文書・skill のみなら参照先・frontmatter・整形を確認する。
Marionette・Patrol・動画編集はこのテンプレートの必須工程ではない。
既存 PR の追加修正では、変更範囲の検証を行い、動画は明示依頼または必要な証拠がある場合に用意する。

## 本文と公開

[PR テンプレート](../../../.github/pull_request_template.md) の見出し順で本文を作り、
具体的な問題と変更後の動作、設計判断、テスト結果をまとめる。
関連 Issue がなければ「該当なし」とし、確認済みの項目だけチェックする。
ビルド成功と端末での操作確認、以前の commit の証跡と現在の検証結果を区別する。
画像は UI の差を説明する場合に添え、ローカル path を GitHub で表示できる URL と扱わない。
既存の有効な添付を保持し、更新が必要なら取得元と範囲を明記する。

利用できる GitHub 連携を優先し、CLI を使う場合は本文を一時ファイルに書いて `--body-file` へ渡す。
公開後に URL・base/head・本文・添付を再取得して確認する。失敗時は作成済みか確認してから不足分だけ再試行する。
同じ失敗が続く場合は原因と未完了の操作を報告し、重複 PR や重複投稿を作らない。
準備が残る場合は draft として残件を明示する。merge は別の依頼がある場合に行う。
